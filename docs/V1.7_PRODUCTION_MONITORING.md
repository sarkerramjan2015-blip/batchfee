# BatchFee v1.7 production monitoring

This runbook is intentionally backend-only. It does not deploy functions, change live data, or expose health records to clients.

## Signals added by v1.7

- Every trusted callable has a correlation ID, operation name, duration, actor UID, and bounded tenant/request identifiers in Cloud Logging.
- Passwords, phone numbers, media, and raw request bodies are never logged.
- Permission/authentication failures are warning-level security events.
- Calls taking 2.5 seconds or longer emit a slow-operation warning.
- Scheduled maintenance keeps one merged health document per job under `platform_health`; no unbounded health history is created.
- Failed scheduled jobs rethrow after recording health, so Cloud Scheduler retry and Cloud Monitoring failure signals continue to work.

## Recommended alerts before v1.7 rollout

1. Cloud Function error rate above 2% for 10 minutes.
2. Five or more `Trusted backend operation failed` logs in 5 minutes.
3. Twenty or more `permission-denied` or `unauthenticated` trusted-call warnings in 5 minutes.
4. Ten or more slow trusted calls in 10 minutes, or p95 callable latency above 3 seconds.
5. `platform_health/subscription_expiry_sweep.lastCompletedAtMs` older than 30 minutes.
6. `platform_health/owner_login_cleanup.lastCompletedAtMs` older than 36 hours.
7. Crashlytics crash-free users below 99%, or ANR rate above 0.5%.
8. Firestore read/write quota above 80% and billing budget thresholds at 50%, 80%, and 100%.

## Useful Cloud Logging filters

Unexpected trusted backend failures:

```text
resource.type="cloud_run_revision"
jsonPayload.message="Trusted backend operation failed"
```

Authorization spikes:

```text
resource.type="cloud_run_revision"
jsonPayload.message="Trusted backend request rejected"
jsonPayload.securityRelevant=true
```

Slow operations:

```text
resource.type="cloud_run_revision"
jsonPayload.message="Trusted backend operation is slow"
```

Scheduled maintenance failures:

```text
resource.type="cloud_run_revision"
jsonPayload.message="Scheduled backend job failed"
```

## Rollout check

After deployment, invoke only non-destructive read/login paths first and confirm correlation IDs appear. Then verify both health documents update on schedule. Do not relax Firestore rules to expose `platform_health`; Admin SDK and Cloud Monitoring are the intended readers.
